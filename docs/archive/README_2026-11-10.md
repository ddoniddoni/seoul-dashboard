# SEOUL PULSE

메인 현황은 모니터용 상황판이다. 1280×800 이상에서 핵심 지표, 서울 지도, 선택 장소의 24시간 인구 흐름과 20곳 전체 목록을 스크롤 없이 배치한다. 상단 **전체화면**으로 메뉴를 숨겨 화면을 채우고 Esc로 돌아온다. 지도나 목록을 선택하면 같은 화면의 그래프가 바뀐다. 작은 화면은 세로 배치이며 상세 탐색은 왼쪽 메뉴에서 제공한다.

왼쪽 메뉴 하단의 **테마 토글 스위치**로 라이트/다크를 전환한다. 켜면 다크, 끄면 라이트이며 현재 모드를 문구로 표시한다. 기본은 다크이고 선택은 브라우저에 저장된다. 접힌 메뉴와 모바일 서랍에도 같은 스위치를 제공한다.

현재 수집 기본값은 **20곳 / 5분**, 화면의 현황과 이력 확인은 **1분**이다. 이력 API와 기록 표는 5분 구간을 사용하고 차트는 시간대별 마지막 관측을 보여준다. 원천 시각이 같은 관측은 중복 저장하지 않으며 최근 24시간만 보관한다. 사용자의 실행 의사 재확인 후 로컬 5분 수집을 재개했다. 첫 배치는 2026-11-10 01:01:57 KST에 완료했으며 인구와 날씨 모두 20곳에서 유효했다. 현재 실행 상태는 collector:local status로 확인한다.

배포용으로 `20261109153947_collect_every_five_minutes.sql`, `COLLECTION_INTERVAL_MINUTES=5`, Cron `*/5 * * * *`를 함께 준비했다. 원격 적용과 Cron 활성화는 미실행이다. DB 일일 상한 6,000회는 유지하며 5분 기본 요청 5,760회 외 재시도 여유는 240회다. 로컬은 재시도하지 않는다.


공개 화면은 실데이터 전용이다. 화면 설정과 데이터 모드 선택을 제공하지 않는다. `/demo`와 이전 `dataset=demo` 링크도 실데이터 화면으로 연결하며, `/api/v1/demo/*`는 404를 반환한다. 합성 fixture는 내부 개발용으로만 유지한다. 실데이터 저장소 설정이 없으면 오류를 표시한다. 아래 과거 데모 실행 기록은 현재 공개 동작과 구분한다.

기본 모니터링은 20곳이다. 강남역, 홍대 관광특구, 명동 관광특구, 여의도, 성수카페거리를 유지하고 주요 역세권, 관광지, 상권과 공원 15곳을 추가했다. 지도, 검색, 상세, 비교와 데모가 같은 목록을 사용한다. 공식 전체 121곳 카탈로그와 기존 로컬 수집본은 보존하며, `capture:seoul --all`은 별도 전체 수집 옵션이다. 과거 121곳 실행 기록은 현재 기본 수집 범위와 구분한다.

배포 전 `20261109150723_expand_monitored_areas_to_twenty.sql` 적용과 환경 변수 `MAX_MONITORED_AREAS=20`, `SEOUL_DAILY_CALL_BUDGET=6000` 반영이 필요하다. 일일 예산은 내부 상한이며 실제 키 허용량 이하로 설정한다. 신규 DB 장소는 기본 비활성이고 원격 DB 변경과 Cron 활성화는 실행하지 않았다. 개발용 로컬 수집은 별도로 재개했다. 로컬 기본 예산은 5분 주기 5,760회이며 선택 10분은 2,880회, 30분은 960회다.

### 로컬 실행

프로젝트 경로는 `/Users/ddoni/dev/seoul-pulse`다. Node.js 24.21.0 LTS와 npm 11.19.0을 사용한다. 현재 이 Mac에는 공식 체크섬을 확인한 프로젝트 전용 런타임이 `.local/node`에 설치되어 있다. 전역 Node.js 설정은 변경하지 않았다.

```sh
cd /Users/ddoni/dev/seoul-pulse
export PATH="$PWD/.local/node/bin:$PATH"
npm run dev
```

기본 접속 주소는 `http://127.0.0.1:3000`이다. 2026-10-16 현재 3000번은 다른 앱이 사용 중이어서 이 프로젝트는 `npm run dev -- --port 3001`로 열었으며 확인 주소는 `http://127.0.0.1:3001`이다. 이 PATH 설정은 현재 셸에만 적용된다. `.local/`은 Git 제외 대상이며 다른 컴퓨터에서는 `.nvmrc` 또는 `.node-version`의 Node.js LTS를 설치/선택한 뒤 `npm ci`로 의존성을 설치한다. `.npmrc`는 잘못된 Node/npm 조합의 설치를 거부한다.

시작 후 `http://localhost:3000`을 연다. 실데이터 저장소 설정이 필요하며 원천 수집은 별도다. `DATA_MODE=live`나 `dataset=live`는 기본적으로 Supabase에 저장된 자료만 읽는다. `LIVE_DATA_BACKEND=local-snapshot`은 개발 환경에서만 명시적으로 수집해 저장한 실제 서울시 자료를 읽는다. DB 설정 누락/조회 실패는 오류로 안내하며 demo로 자동 전환하지 않는다. DB가 비어 있으면 관측 없음으로 표시한다. 현재 DB는 미설정이다. 2026-10-15 08:58에 승인된 전체 단일 배치로 121곳의 인구/혼잡도와 119곳의 날씨를 수집했고, 현재 로컬은 live/local-snapshot 모드로 표시한다.

### 대시보드와 시연

| 경로 | 현재 제공 기능 |
| --- | --- |
| `/demo` | `/?dataset=demo&area=POI014`로 이동하는 시연 시작점 |
| `/` | 서울 위치 개요 중심의 대시보드. 좌측 KPI/최신성, 중앙 지도, 우측 선택 상세, 하단 24시간 차트/장소 탐색/자료 시각 표 |
| `/areas/[areaCode]?dataset=demo` | 공유 가능한 동일 장소 상세. 미등록 코드는 404 |
| `/compare?dataset=demo&places=POI014,POI007,POI003` | 최대 3곳의 현황, 동일 축의 24시간 인구 그래프, 범위 비교 표와 링크 공유 |
| `/data-info?dataset=demo` | 합성 데이터 구분, 추정 인구와 시각 해석, 최신성 정책과 공식 출처 |

상단의 시연 상태 선택기로 기본 현황, 첫 로딩, 조회 오류, 빈 데이터, 부분 누락, 갱신 지연과 기록 수집 중 상태를 선택한다. `scenario`도 URL에 저장하므로 같은 조건을 공유할 수 있다. 예: `/?dataset=demo&area=POI014&scenario=partial`.

장소 선택과 검색/필터/정렬은 URL을 따른다. 필터 밖의 선택 장소도 상세를 유지한다. KPI는 필터와 무관한 전체 시연 장소를 기준으로 계산하며, 지연/누락 값을 최신 붐빔/여유 집계에 넣지 않는다. 시계열은 채움 없이 추정 범위 중앙선 하나를 표시하고 결측을 연결하지 않는다. 최소/최대 추정 범위는 툴팁과 기록 표에서 확인한다. 같은 기록을 표로도 열 수 있다.

후속 첫 화면 개선으로 정적 서울 위치 개요를 추가했다. 자치구 25개는 서울시 공개 격자 지도의 2025년 6월 30일 기준 경계이며, 전체 공식 장소 121곳의 표시 좌표와 영역을 지원한다. 데모와 기본 실데이터 화면은 공식 카탈로그에서 선택한 20곳을 표시한다. 장소 도형은 기존 공식 영역 ZIP에서 추출했다. 구별 혼잡도를 채색하거나 임의 좌표/도형을 만들지 않았다. 지도 표식과 목록은 동일한 URL 선택과 필터를 사용한다.

첫 `/` 접속은 현재 기본 데이터셋과 강남역을 선택한 명시적인 URL로 이동한다. 쿼리에 명시한 데이터 모드와 선택 해제는 유지한다. 상단 화면 설정을 펼치면 모드와 시연 상태를 변경할 수 있다.

MapLibre 카메라/확대축소와 전체 GIS 검증, 즐겨찾기, 7일 조회와 CSV는 M4로 남겼다. 2026-11-08에 최대 3곳의 24시간 장소 비교 화면을 추가했다. 반응형 CSS와 키보드용 링크/버튼/포커스 표시는 구현했지만 실제 브라우저, 390px/1440px과 접근성 동작은 사용자 테스트 실행 지시가 없어 미검증이다. 정적 지도 출처와 가공 범위는 [지도 메타정보](../../docs/sources/seoul-overview.meta.json)에 있다. `python3 scripts/build-overview-map.py`는 보관한 공개 원본만 읽어 표시 경로를 다시 만든다. 네트워크와 키 접근은 없다.

설정이 필요하면 `.env.example`을 참고해 로컬 `.env.local`에 직접 작성한다. 기존 로컬 설정을 덮어쓰지 않는다. 비밀값을 대화에 붙여 넣거나 `NEXT_PUBLIC_` 접두사로 노출하지 않는다. M0에서 확인한 장소와 원천 계약은 [M0 확인 기록](../../docs/M0_VERIFICATION.md), [초기 장소 카탈로그](../../docs/initial-area-catalog.json)에 있다.

M0 후속 조사에서 예시 파일에 입력된 키를 `.env.local`로 옮겼다. 당시 실제 키의 강남역 HTTP 1회 조회는 성공했지만 앱 화면에는 연결하지 않았다. 2026-10-15의 실제 화면 연결은 아래 개발 수집본 절을 따른다. HTTP 승인은 이번 로컬 단일 조회에만 적용하며 `SEOUL_ALLOW_INSECURE_HTTP` 기본값은 false로 유지한다. [실응답 구조와 전송 확인](../../docs/03_DATA_AND_API.md#실응답에서-확인한-구조)을 다음 adapter 구현의 근거로 사용한다.

| 명령 | 용도 | M1 실행 여부 |
| --- | --- | --- |
| `npm run dev` | 로컬 개발 서버 | M1 미실행. M0에서는 기동 로그만 확인 |

M0~M2의 단위 테스트 54개에 M3 사례 23개를 추가했다. 단위 77개, 로컬 DB 통합 2개와 pgTAP 12개 검사를 작성했으며 모두 미실행이다. 테스트는 사용자 실행 지시가 있을 때만 수행한다. lint/typecheck/build와 SQL 문법 확인을 테스트 성공으로 간주하지 않는다. React Doctor의 변경 비교는 Git `HEAD`가 없어 실행되지 않았으며 Git 초기화로 우회하지 않았다.

조회는 기존 TanStack Query 5.104.2를 사용한다. 사용자 요청에 따라 디자인은 Material UI 9.5.0, 공식 아이콘 9.5.0, 무료 MUI X Charts 9.15.0으로 통일했다. react-is는 React와 같은 19.3.0을 유지한다. 설치 시 fsevents/unrs-resolver 스크립트 승인 경고가 있었고 추가 승인하지 않았다. 공식 문서는 [TanStack Query 서버 초기 데이터](https://tanstack.com/query/latest/docs/framework/react/guides/advanced-ssr), [MUI Next.js 통합](https://mui.com/material-ui/integrations/nextjs/), [MUI X 선과 결측 옵션](https://mui.com/x/react-charts/lines/)을 참고했다.

### 디자인 구현 기준

앞으로 모든 UI 디자인 작업은 MUI를 사용한다. 기존 대시보드, 안내, 오류와 404 화면도 MUI로 전환했다. 버튼/입력/선택/필터/카드/목록/표/상태/로딩/접기 영역과 아이콘을 같은 테마로 구성한다. 색상/숫자 글꼴/간격/반응형 토큰은 `src/theme/tokens.ts`, 컴포넌트 기본값은 `src/theme/theme.ts`, 화면 조정은 `sx`가 기준이다.

Next.js 16 App Router에는 공식 스타일 캐시 provider와 Emotion을 연결했다. Tailwind/Recharts와 PostCSS 설정은 제거했다. 공식 지도 도형은 보관된 벡터 자산을 사용하고 패널/표식/설명에는 MUI를 적용한다. 차트는 시간별 마지막 관측의 추정 범위 중앙값을 막대로 표시하며 결측을 null로 유지한다. 원래의 상하한은 툴팁과 기록 표에 보존한다. 같은 기록의 텍스트 요약과 MUI 표도 제공한다.

현재 화면/상호작용의 브라우저 검증과 작성한 테스트는 사용자 실행 지시가 없어 미실행이다. MUI 전환과 M3의 검증/남은 항목은 `PROGRESS.md`를 따른다.

### 워크스페이스 메뉴

왼쪽 사이드바에서 종합 현황(`/`), 장소 탐색(`/places`), 지도 보기(`/map`), 장소 비교(`/compare`), 자료 상태(`/data-status`), 데이터 안내(`/data-info`)로 이동한다. 데스크톱에서는 햄버거 버튼으로 사이드바를 접어 현황판을 넓힐 수 있고, 모바일에서는 같은 버튼으로 서랍 메뉴를 연다.

목록과 지도에서 장소를 선택하면 `/areas/[areaCode]`에서 해당 장소의 인구 흐름과 환경 정보를 확인한다. 검색/정렬/필터와 비교 선택은 URL로 유지하며, 실제와 시연 데이터 표시는 모든 화면에 유지한다.

### 장소 비교 사용법

도시 현황의 장소 목록에서 “비교에 추가”를 눌러 2~3곳을 선택한 뒤 하단의 “비교하기”로 이동한다. 왼쪽 “장소 비교” 메뉴에서도 장소명을 검색해 선택할 수 있다. 선택한 코드는 URL의 places에 저장되며 검색/목록 이동에도 유지된다. 최대 3곳을 선택한 상태에서는 한 곳을 해제한 뒤 다른 장소를 추가한다.

상태 카드에는 마지막 추정 인구 범위, 혼잡도, 원천 기준 시각, 수집 시각과 최신성을 표시한다. 그래프는 한 응답의 동일한 24시간 범위와 동일한 인구축을 사용한다. 시간별 대표값은 각 시간의 마지막 유효 관측 범위 중앙값이며 관측 없는 시간은 비워 둔다. “시간별 범위 비교 표”에서 실제 범위와 관측 시각을 확인한다. “비교 링크 공유”는 현재 선택과 데이터 모드를 담은 링크를 제공한다.

비교 조회는 저장된 자료만 읽으며 서울시 수집을 유발하지 않는다. 시연과 실데이터의 캐시는 분리한다. 현재는 24시간만 지원하고, 링크는 조회 조건을 공유할 뿐 자료 시점을 고정하지 않는다. 구현 및 검증 범위는 PROGRESS.md 36절을 따른다.

### M2 API adapter

`src/lib/server/seoul/`의 client와 adapter는 서버에서만 사용할 수 있다. 등록 장소와 확인한 HTTP origin만 허용하고, 8초 timeout, 8 MiB 스트림 제한, redirect 거부와 XML 선언/깊이 검사를 적용한다. 인구와 날씨는 독립적으로 정규화하며 원천 시각을 수신 시각으로 대체하지 않는다. 공개 화면이나 새로고침에서 이 client를 호출하지 않는다.

`npm run verify:seoul -- --help`는 사용법만 출력한다. `npm run verify:seoul`의 기본 동작도 설정 확인만 수행하고 원천 요청은 0회다. 실제 확인은 **별도 실호출 실행 지시를 받은 뒤** 아래처럼 한 장소만 실행한다. 이전 강남역 1회 HTTP 승인은 이미 사용했다.

```sh
npm run verify:seoul -- --execute --area=POI014 --source-time-zone=Asia/Seoul --allow-insecure-http-once
```

키/주소는 로컬 서버 환경에서 읽고 명령행 키를 받지 않는다. HTTP 옵션은 해당 실행에만 적용하며 DB 쓰기, 자동 재시도와 예약 활성화를 포함하지 않는다. 출력은 정규화된 값/시각, 제한된 진단 코드와 전송 크기/소요시간이다. 원본 XML, 인증 URL, 비밀과 원본 오류 메시지는 출력하지 않는다.

원천 시각의 공식 시간대는 미확인이므로 자동 기본값을 두지 않는다. 위 옵션 또는 `SEOUL_SOURCE_TIME_ZONE=Asia/Seoul`은 실행자가 선택한 해석 기준이지 서울시가 보증한 시간대가 아니다. 기온(℃)/습도(%)는 [공식 화면 코드](https://data.seoul.go.kr/SeoulRtd/js/domain/weather.js)와 API 필드 설명으로 확인했다. PM25는 공식 코드에 ㎍/㎡와 ㎍/㎥ 표기가 혼용돼 `null`과 `pm25-unit-unconfirmed`로 남긴다. [단위 확인 기록](../../docs/sources/seoul-weather-units-20261014.json)을 참고한다.

`tests/fixtures/seoul/`의 정상 fixture는 이전에 승인된 강남역 응답 전체를 재사용했다. 실패 fixture는 합성 사례임을 파일명과 주석으로 표시했다. 실제 실패 envelope는 미검증이다. 전체 121곳의 성공 응답 수집과 별개로 새 계약 테스트는 사용자 실행 지시 전까지 실행하지 않는다. 외부 설정이 없는 기본값은 합성 데이터이며, 현재 로컬 설정은 아래 개발용 실제 수집본을 표시한다.

### 개발 화면에서 실제 API 수집본 보기

현재 로컬 확인 결과: 사용자가 121곳의 단일 평문 HTTP 조회를 명시 승인해 2026-10-15 08:58:31 한국 시간에 수집을 마쳤다. 원천 요청은 정확히 121회이고 각 장소 1회이며 재시도는 없다. 인구/혼잡도는 121곳, 날씨는 119곳에서 유효 자료를 받았다. 가산디지털단지역과 서울대공원은 날씨가 제공되지 않아 자료 없음으로 표시한다. 인구 원천 기준은 같은 날 08:25~08:30, 날씨는 08:50이며 수집 완료 시각과 구분한다. 기존 5곳은 실제 관측 2개씩, 신규 116곳은 1개씩으로 총 126개이고 빈 과거는 채우지 않는다. [실데이터 화면](http://127.0.0.1:3001/?dataset=live&area=POI014)에서 확인한다. 이는 2026-10-15 단일 배치의 기록이며 해당 121회 승인은 사용을 마쳤다. 2026-10-16 추가한 10분/30분 선택 정기 수집의 실제 실행 상태와 결과는 PROGRESS.md의 최신 기록과 collector:local status를 따른다.

Supabase 설정 없이 실제 자료를 화면에 연결할 때만 쓰는 개발용 경로다. 원격 DB나 운영 저장소를 파일로 대체하지 않으며 `NODE_ENV=production`에서는 읽기/쓰기를 거부한다.

```sh
npm run capture:seoul -- --help
# 아래 명령은 20개 장소를 각 1회 실제 조회하므로 실행 지시와 HTTP 전송 승인이 필요하다.
npm run capture:seoul -- --execute --source-time-zone=Asia/Seoul --allow-insecure-http-once
# 전체 공식 121곳. 이 범위에 대한 새 HTTP 전송 승인을 받은 뒤에만 실행한다.
npm run capture:seoul -- --all --execute --source-time-zone=Asia/Seoul --allow-insecure-http-once
```

수집에 성공하면 기존 `.env.local`의 비밀을 유지하면서 `LIVE_DATA_BACKEND=local-snapshot`, `DATA_MODE=live`를 설정하고 `/` 또는 `/?dataset=live&area=POI014`를 연다. `SEOUL_ALLOW_INSECURE_HTTP=false`와 `COLLECTOR_ENABLED=false`는 유지한다. 위 HTTP 옵션은 해당 단일 배치에만 적용되며 다음 실행이나 예약 수집 승인이 아니다.

표시할 인구 범위/혼잡도/기온/습도와 각 기준/수집 시각만 `.local/data/seoul-snapshot.json`에 저장한다. 원본 XML과 인증 URL은 저장하지 않는다. PM25는 기존 단위 확인 정책에 따라 누락으로 남긴다. 파일은 Git 제외 경로에 0600 권한으로 원자적으로 저장하며 공개 조회는 파일만 읽는다. 파일이 없거나 잘못되면 live 오류이고 합성 값으로 바꾸지 않는다.

기본 명령은 모니터링 20곳, `--all`은 공식 전체 121곳을 순차 조회하며 각 장소를 한 번만 요청하고 자동 재시도는 없다. 요청 사이 250ms를 두고 기본 배치는 최대 150초, --all 배치는 최대 10분에 중단한다. 코드가 연속 번호라고 가정하지 않으며 공식 XLSX의 실제 목록만 사용한다. 같은 10분 슬롯의 중복 실행은 중지하고, 동시 실행은 잠금 파일로 막는다. 인증/요청 제한 응답은 뒤의 요청을 중지한다. 기존 유효 자료는 실패/누락 시 원천 시각과 함께 유지하며, 실제 관측만 중복 시각을 병합해 최근 24시간/전체 합계 100,000개 이내로 보존하고 수집본 파일 상한은 32MiB다. 최신값은 이력과 별도로 유지한다. 개발용 정기 수집과 단일 수집은 로컬 파일 잠금/일일 요청 원장을 공유한다. 이 경로의 잠금과 원장은 단일 컴퓨터에서 사용한다. 운영 DB의 분산 lease는 별도로 유지한다.

첫 실제 수집에는 과거 24시간 이력이 없다. 그래프는 실제 관측점 하나와 기록 수집 안내를 표시하고 빈 시간을 채우지 않는다. 이후 별도로 승인해 실행한 수집에서 같은 원천 시각은 중복 기록하지 않고 새 원천 시각부터 이력이 늘어난다. 전체 장소의 지도 표식을 표시하고 선택한 장소의 이름과 범위만 펼친다. 목록은 5곳을 넘으면 3곳씩 페이지를 나누며 검색/필터는 전체 목록에 적용한다. 페이지 상태는 URL에 보관하고 지도에서 선택하면 해당 장소가 있는 목록 페이지를 연다. 화면의 다시 조회와 자동 확인은 저장된 수집본을 읽을 뿐 서울시 API를 호출하지 않는다. `/demo`는 별도 합성 데이터로 유지한다.

### 개발용 정기 수집 (기본 5분, 선택 10분/30분)

로컬 실행 기록 (2026-10-16): 사용자가 10분마다 반복 평문 HTTP 전송을 명시 승인해 한국 시간 17:33:26에 전체 121곳의 정기 수집을 시작했다. 첫 배치는 17:34:11에 완료했고 원천 요청 121회, 인구/혼잡도 121곳과 날씨 119곳이 유효했다. 인구 원천 기준은 17:05, 날씨는 17:30으로 수집 완료 시각과 구분한다. 실행 중 여부와 다음 예정은 `npm run collector:local -- status`, 상세 결과는 PROGRESS.md의 최신 기록을 따른다.

2026-10-16 요청에 맞춰 `collector:local` 명령을 추가했다. 현재 로컬의 `DATA_MODE=live`, `LIVE_DATA_BACKEND=local-snapshot`에서만 사용하며 production에서는 거부한다. 시작하면 즉시 수집을 시도하고 이후 실행 시작 기준 선택한 주기(기본 5분, 선택 10분/30분)마다 모니터링 20곳을 각 1회 순차 조회한다. 같은 수집 구간/프로세스 중복을 막고 작업은 최대 150초에 중단한다. 밀린 작업을 한꺼번에 따라잡지 않는다.

```sh
# 아래 두 명령은 원천 요청을 하지 않는다.
npm run collector:local -- start
npm run collector:local -- start --interval-minutes=30
npm run collector:local -- status
# 반복 평문 HTTP 키 전송에 대한 명시 승인을 받은 뒤 실행한다.
npm run collector:local -- start --interval-minutes=5 --execute --source-time-zone=Asia/Seoul --allow-insecure-http-recurring
# 30분을 승인받았다면 위의 --interval-minutes=5를 --interval-minutes=30으로 바꾼다.
# 중지와 확인
npm run collector:local -- stop
npm run collector:local -- status
# 키/권한 복구 또는 요청 제한 해제 후 일시 중지만 명시적으로 해제한다.
# 키 환경변수를 바꿨다면 stop/start로 프로세스를 다시 시작한다.
npm run collector:local -- resume
```

일반적인 요청량과 KST 일일 예산은 기본 5분 5,760회, 선택 10분 2,880회, 30분 960회다. 실행 중 주기를 바꾸려면 stop 후 새 주기로 start하며 같은 날의 누적 요청량은 유지한다. 요청 시작 전에 영속 예약하며 실패/중단도 차감하고 자동 재시도하지 않는다. 예산은 한국 시간 날짜가 바뀌면 다시 계산한다. 인증 오류는 수동 해제 전까지, 요청 제한은 Retry-After(없으면 15분, 최소 3분)까지 이후 호출을 멈춘다. 수집 실패/누락/과거 응답은 직전 유효 값의 원천 시각을 보존하고 같은 장소/원천 시각의 관측을 중복 추가하지 않는다.

상태/예산/중지 요청/로그는 .local/data의 비공개 파일에 저장한다. 상태 heartbeat는 5초이고 30초 이상 확인되지 않으면 화면에서 중지로 구분한다. 화면과 공개 API는 읽기 전용 상태와 저장된 자료만 읽으며 수집 코드를 import하지 않는다. 수집 중/대기/일시 중지/중지 상태와 다음 예정 시각을 표시한다. 로그는 약 5MiB에서 이전 파일 한 개를 남겨 순환한다.

이력은 저장 완료 시점 기준 최근 24시간만 보관한다. 20곳의 기본 5분 주기는 하루 최대 5,760개, 선택 10분은 2,880개, 30분은 960개 관측이 추가될 수 있다. 다음 수집 저장에서 오래된 이력을 정리하며 조회만으로 파일을 수정하지 않는다. 기존 파일 호환성과 안전을 위한 100,000개/32MiB 상한을 유지하고 원본 XML/키/인증 URL은 저장하지 않는다.

정기 실행 승인은 기존 단일 121회 HTTP 승인과 별개다. 전송 허용은 해당 프로세스의 명시 옵션에만 적용하고 `.env.local`의 전역 HTTP 및 기존 DB 수집 활성화 설정은 변경하지 않는다. 개발 컴퓨터가 꺼지거나 프로세스가 종료되면 수집도 멈추며 OS 시작 예약/원격 Cron/배포는 추가하지 않는다. 운영용 Supabase는 기존 10분/5곳의 미활성 준비 상태로 남긴다. 실제 시작/최초 배치/연속 주기의 확인 결과는 PROGRESS.md에 기록한다.

### M3 DB와 수집

`supabase/migrations/20261014115659_seoul_pulse_storage_and_collection.sql`은 공식 장소 5곳만 초기화한다. 최신값/인구 이력, 비공개 실행/lease/일일 예산/시도 원장, RLS와 RPC를 함께 정의한다. 모든 장소는 수집 비활성으로 시작하며 가짜 관측은 넣지 않는다. 이번 개발에서 migration을 적용하거나 DB를 생성하지 않았다.

공개 페이지와 `/api/v1/live/{overview,areas,history,status}`는 publishable key 기반 읽기 경로를 사용한다. `/api/v1/live/areas/POI014`로 공개 장소 상세를 읽는다. 공개 조회/새로고침은 서울시 API를 호출하지 않는다. `history?places=POI014&range=24h`는 실제 저장 관측의 10분 버킷을 반환하며 결측, 관측 시각과 부분 버킷을 보존한다. 최대 3곳의 24시간 비교 화면은 구현했으며 7일/CSV는 M4에 남겼다. demo도 같은 공개 경로를 제공한다.

live 조회에는 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`만 필요하다. 최신 `sb_publishable_`/`sb_secret_` 키를 구분하고 레거시 JWT 키는 받지 않는다. 수집만 secret key와 서울시 설정을 사용한다. 보호된 `POST /api/internal/collect`는 Bearer 인증을 먼저 확인하고 쿼리 없는 빈 JSON 객체만 받는다.

수집은 DB 기준 10분 슬롯, 120초 lease, 원자적 시도 예약과 일일 안전 상한을 사용한다. 원천 동시성은 2, 일시 장애 재시도는 최대 1회다. 같은 원천 시각은 중복 행을 만들지 않고 수정 시 revision을 높인다. 오래된 응답/실패는 직전 정상값과 원천 시각을 보존한다. 인구 이력과 최신값은 같은 트랜잭션에서 저장한다.

```sh
npm run collect:once -- --help
```

위 명령은 사용법만 표시한다. `npm run collect:once`도 설정 존재 여부만 출력하며 DB/원천 요청은 없다. `--execute`는 활성 장소에 실제 쓰기/HTTP 호출을 수행하므로 **별도 실행 지시와 전송 승인이 필요하다**. 기존 로컬 HTTP 1회 승인은 재사용하지 않는다. `COLLECTOR_ENABLED=false`와 `SEOUL_ALLOW_INSECURE_HTTP=false`를 유지했다.

적용 순서, 테스트 DB 조건, 예약/해제/인증 장애 복구 템플릿과 검증 한계는 [Supabase 운영 안내](../../supabase/README.md)에 있다. 템플릿 파일 작성은 DB 적용이나 운영 활성화가 아니다. 관련 공식 기준은 [Supabase API 키](https://supabase.com/docs/guides/getting-started/api-keys), [함수와 실행 권한](https://supabase.com/docs/guides/database/functions), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Cron](https://supabase.com/docs/guides/cron/quickstart)을 따른다.

### 만들 결과물

서울의 선택한 장소를 지도에서 탐색하고, 장소별 추정 인구 범위와 혼잡 단계, 직접 수집한 시간대별 변화를 비교하는 웹 대시보드다. 초기에는 5개 장소를 운영하고 실제 사용량을 확인한 뒤 확장한다.

핵심은 숫자가 빠르게 움직이는 연출이 아니라, 외부 데이터 수집부터 시각화, 장애 복구와 출처 표시까지 연결된 완성도다.

### 시작 방법

새 프로젝트라면 이 패키지의 내용물을 프로젝트 루트에 둔다. 기존 프로젝트라면 AGENTS, README, 환경변수 예시와 진행 문서를 덮어쓰지 않고 병합한다.

`.env.example`은 자리표시자와 정책 기본값만 담는다. 실제 값은 로컬 `.env.local` 또는 배포 환경의 비밀 설정에 입력한다. 발급받은 키를 Codex 대화에 붙여 넣을 필요는 없다.

아래는 최초 M0 시작용 지시문이다. 현재 M0 결과는 `PROGRESS.md`에 기록되어 있으며 다음 단계는 별도 지시 후 진행한다.

```text
AGENTS.md, README.md, PROGRESS.md와 docs/05_CODEX_PLAN.md를 읽어줘.
기존 저장소와 사용자 변경을 먼저 확인하고, 현재 단계인 M0만 진행해줘.

Next.js, React, TypeScript와 npm 환경을 확인하고 필요한 최소 기반을 구성해줘.
서울시 API 계약과 장소 카탈로그를 공식 문서 및 로컬 환경변수로 검증해줘.
비밀값이나 인증키가 포함된 요청 URL은 출력하지 마.
키, 파일 또는 네트워크가 없으면 검증하지 못한 항목을 명시하고,

M0 결과를 보고한 뒤 다음 단계로 넘어가지 말고 멈춰줘.
```

### 중요한 경계

원본 문서 패키지에는 검증된 장소 목록과 전체 응답 스키마가 없었다. M0에서 공식 목록 원본과 초기 5곳의 코드/명칭을 확보했으며 `docs/M0_VERIFICATION.md`에 근거를 기록했다. 강남역 실호출로 인구/날씨 경로를 확인한 뒤 전체 121곳의 실제 인구/혼잡도와 119곳의 날씨 응답을 수집했다. 오류/결측을 포함한 전체 API 계약과 자동 테스트는 미검증이다.

실제 과거 차트는 수집을 시작한 시점 이후부터 채워진다. UI 개발은 별도 데모로 진행하고, 실데이터 화면의 비어 있는 과거 구간은 그대로 설명한다.

무료 데이터 이용과 웹 서비스의 무제한 무료 운영은 다르다. 실제 배포 전 호출 허용량, 호스팅 사용량, DB 용량, 지도 배경 서비스 조건을 확인한다. 이 패키지는 유료 배경지도나 실시간 WebSocket 서버를 필수로 요구하지 않는다.

### 최근 24시간 보존 정책 (2026-11-09)

시연은 현재 현황과 최근 24시간의 실제 인구 흐름을 제공한다. 운영 DB 정리 migration과 매시 23분 예약 템플릿을 준비했으며 아직 DB에 적용하거나 예약을 활성화하지 않았다. 원천 관측 시각이 24시간을 지난 인구 이력만 삭제하고 장소별 최신값은 유지한다. 정상 정리 간격 동안 약 1시간의 삭제 대기분이 남을 수 있다. 운영 로그는 장애 확인을 위해 기존 14일 보존을 유지한다. 7일 이력은 현재 제품 범위에서 제외하며, 121곳 운영 수집 분할과 실제 배포는 별도 후속 작업이다.
